## F1: The dead-air threshold has four mutually exclusive values across two binding specs, the config, and the code that cut the thirteen shipped hearings
SEVERITY: blocker
EVIDENCE: `spec/SPEC.md:316` (rank 1, the contract) — "Dead air over **4 seconds** removed inside each chapter."; but `spec/SPEC.md:142` in the same file — "Pauses STAY. This supersedes the four-second dead-air rule, which was cutting the tension out of every hearing. Only a black screen or an explicit recall is removed."; `spec/CONTENT_SPEC.md:62` — "Dead air longer than 25 seconds is removed."; `config/pipeline.yaml:138` — "dead_air_s: 25.0         # was 4.0; see above. Not his rule, a stand-in."; `scripts/cut_shortlist.py:9-11` — "pauses STAY. Nothing is trimmed for silence here … and the four-second rule that used to strip them is gone"; and `STATE.md:222` records the shipped monkey render as "dead air >4.0s removed, 825s -> 808s". `config/pipeline.yaml:117` quotes CONTENT_SPEC §2 as saying "Dead air longer than 4 seconds is removed" — text that no longer exists in that file. Four values (0s / 4s / 25s / "black screen only") are simultaneously live, and `STATE.md:16-22` then says every silence pass before 2026-08-28 used `silencedetect`, which "returns ZERO spans" on this footage at -30/-25/-20/-18 dBFS, so the 25s number was never actually applied either.
WHY-IT-MATTERS: A session that opens SPEC.md — which `CLAUDE.md:12` orders it to read second and which says at `spec/SPEC.md:3-4` "if anything else in the repo disagrees with it, this wins" — will implement 4s, which SPEC's own §2 already retracted as the thing that "was cutting the tension out of every hearing". Nathan stated this rule once, verbatim, and it has been re-broken three times.
PROPOSAL: Delete the "4 seconds" clause at `spec/SPEC.md:316` and replace it with a pointer to CONTENT_SPEC §2 as the single numeric home; fix the stale quotation at `config/pipeline.yaml:117`; extend `tests/test_pipeline.py:946` with an assertion that SPEC.md contains no second dead-air number.
COST: ~20 minutes, zero runtime risk (documentation plus one config comment). The cost of not doing it is re-rendering every long-form at the wrong threshold.
