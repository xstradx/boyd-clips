# leaf-5.1 — intent archaeology

Method note: every intent claim below is sourced to a commit message, a docstring, a
STATE.md paragraph or a spec line, with a SHA or a path:line. Where the repo does not
record an intent, I say so instead of inferring one from a filename.

### Timeline — the build arc in date order

**Phase 1, 2026-08-09 to 08-11 — "the automated daily clipper" (commits 429e43a … cc002de).**
The founding commit is literally titled *"Automated daily clipping pipeline for a public
court livestream"*. What it built is coherent and complete on paper: a Python package
`src/boydclips` with a stage per README row — discover, transcribe, segment, gate+score,
select, render, publish — a `cli.py` exposing 18 verbs, a config file holding every
threshold, a SQLite store, and `run_daily.ps1` to be registered with Task Scheduler at
19:40. The goal is stated in `run_daily.ps1:1-8` and `README.md:57-66`: an unattended
overnight run. The design decision the README is proudest of (`README.md:30-33`) is real
and still correct: analyse free captions, download only the minutes that ship. By
2026-08-11 the archive backfill lands (4dc50aa) and `state/pipeline.db` fills with 1,701
dockets and 757 scored cases. **This phase left behind a working skeleton whose every
later contact with reality was made outside it.**

**Phase 2, 2026-08-19 — "the rubric was fitted to the wrong thing" (32d39b2, d6bff6d …).**
Measurement arrives and overturns the founding assumptions. d6bff6d: the old dimensions
"were fitted to a single competitor channel and rewarded the defendant reacting … that is
what loses". 32d39b2: "The unit was wrong. A case-level score averages one devastating
exchange against fifteen procedural minutes." Both rewrites are honest and both are
additive — the new moment scorer (`moments.py`, `momentrun.py`) is bolted alongside the
case scorer rather than replacing it, and `cli.py:6-7` ends up offering both
`boyd run --case` and `boyd run --moment`. **This is the first fork that never closed.**
This is also the last date on which substantial work entered `src/boydclips`: eight of the
twelve commits touching the package are dated 08-09 to 08-19.

**Phase 3, 2026-08-20 — the ground-truth crisis and the review-tool thrash.**
3252734 states the problem exactly: *"Every weight in this project is fitted to a rival
channel, because publications has zero rows and there is no data about Nathan's own
audience."* The answer chosen was to build a rating UI and harvest 30 labels. Five commits
in one day (3252734 → 5db6108 → 2906f58 → e6d51bc → a9db042) build a server, replace it
with a file "because the served version kept vanishing", fix browser-storage failure, fix
a JavaScript syntax error that "made every button inert", and then reverse back to the
server on the grounds that the file version loses answers. 28 labels came out. 7de4742
refits the scorer to them and says so plainly: *"that is circular — the weights were
fitted to those labels."* **Phase 3 left behind two rating tools, a 28-row label set, and
a scorer whose own commit message says its improvement may be noise.**

**Phase 4, 2026-08-21 — Nathan re-specifies the product and it stops being a moment.**
1d83d26 records his words — 8-20 minutes, not 50 — and states *"The unit is the HEARING,
not a 60-second moment."* fef1220 takes his boundary phrase — *"the video of that defendant
should always start with 'the court is calling'"* — and builds `find_called_hearings.py`
around it. Same day, 0a53bfd builds the editing page "that was promised three times",
ccd083c and 48929d2 extend it. **Phase 4 left behind a fifth product unit, a sixth
selection mechanism, three more HTML editors — and did not retire any of the earlier ones.**

**Phase 5, 2026-08-22 to 08-27 — the editor is abandoned; craft moves to thumbnails.**
`HANDOVER-2026-08-23.md:76-84` records the outcome in his words: *"I still don't like it /
Too cluttered / Cutting doesn't work it cut but it was off"* and *"He ended up editing in
CapCut instead."* The first published video (Thompson) goes up by hand — STATE.md:193
quotes him: *"i alreADY POSTED THE THIMPSON"*. Thumbnail builders v2 → v3 → v4 → v5 follow,
each refuting the evidence base of the last (v3's docstring: v2 was built on a research
file "which is wrong on the single most important point").

**Phase 6, 2026-08-28/29 — the craft layer gets genuinely good, and is wired to nothing.**
c56d8b5 finds that `silencedetect` returns zero spans on this footage at four thresholds,
so *"every dead-air pass in this repo was blind"*, and replaces it with word-gap cuts and
audio-visual speaker correlation measured 9/9. 1e56ef1 wraps it as `make_short_auto.py`,
"five gates, all three cases pass". babc7b3 records Nathan picking Q3 for thumbnails. Then
`run_case.py`, `make_thumbnail_auto.py`, `pick_plate.py`, `verify_set.py` and
`config/cases.json` are written as "the routine" — and left **untracked**. None of this
layer imports `boydclips`. **Phase 6 left behind the best code in the repo, sitting
outside both git and the package.**

The shape of the arc: the automation spine was built first and never revisited; every
subsequent discovery was implemented beside it rather than inside it; and the thing that
now produces videos is a hand-populated JSON plus a subprocess driver that git has never
seen.

## F1: The daily driver was built once on day one and still calls a code path untouched since 2026-08-19, so the "automated daily pipeline" now automates the abandoned half of the repo
SEVERITY: blocker
EVIDENCE: `git log --format='%h %ad %s' -- run_daily.ps1` returns exactly one commit, 429e43a 2026-08-09. Its stated intent is at run_daily.ps1:1-8 ("Daily driver. Register with Task Scheduler … 19:40 is deliberate"). Its two payload lines are run_daily.ps1:41 `python -m boydclips.cli doctor` and run_daily.ps1:44 `python -m boydclips.cli run`. `boyd run` reaches `Pipeline.run_daily` (src/boydclips/cli.py:136 → src/boydclips/pipeline.py:689), which calls `render.detect_silences` at src/boydclips/pipeline.py:294 and `render.plan_silence_trim` at pipeline.py:299, and that detector is still `silencedetect` at render.py:598. Commit c56d8b5 (2026-08-29) measured that detector returning "ZERO spans on this footage at -30/-25/-20/-18 dBFS — the courtroom room tone never drops that low, so every dead-air pass in this repo was blind", and STATE.md:184 still lists it under "What is NOT fixed". The corrected path (scripts/tighten_short.py, scripts/who_speaks.py, scripts/caption_short.py, scripts/make_short_auto.py) has exactly one caller in the whole repo — scripts/run_case.py:109 — and run_daily.ps1 does not mention it.
WHY-IT-MATTERS: The one artefact whose entire purpose is unattended operation is wired to the only rendering path that is known-broken. If Nathan registered the scheduled task tonight as README.md:59-62 instructs, it would run every night and emit long-forms with the gaps nobody measured, and would never touch a line of the 2026-08-29 work.
PROPOSAL: Make run_daily.ps1 a thin shell over one Python entry point and move the driver logic into the package as `boydclips.daily`, so exactly one place says what a day does. Concretely: fold scripts/run_case.py's stage list into `Pipeline.produce`, replace `render.detect_silences`/`plan_silence_trim` with the word-gap planner from tighten_short.py promoted to `boydclips/gaps.py`, and make `boyd run` call it. run_daily.ps1 then keeps its yt-dlp refresh, its log tee and its exit codes and gains nothing else — which is what a scheduler hook should be.
COST: Two to three days. Risks breaking `boyd run --case` and `boyd run --moment`, both of which currently work against render.py semantics; and `plan_silence_trim` is depended on by scripts/rebuild_longform.py and scripts/build_case_longform.py:35-37, so those move with it or get pinned.

## F2: `src/boydclips` was meant to be the pipeline; the work migrated to `scripts/` and the newest, best layer imports none of it, so the package is now a library nothing current calls
SEVERITY: blocker
EVIDENCE: Intent is explicit at src/boydclips/cli.py:1-20 (a docstring listing 18 `boyd` verbs) and README.md:70-83 (a command table). Volume: `git log -- src/boydclips` returns 25 commits, 21 dated 2026-08-09 to 08-19 and only one after 08-20 (c56d8b5); `git log -- scripts` returns 39 commits, 24 on or after 08-19. Tracked counts: `git ls-files src` = 23 files, `git ls-files scripts` = 141. Of 128 .py files in scripts/, 50 import `boydclips` and 35 shell out to ffmpeg directly. The current shorts chain does neither halfway measure — `grep -n "^from \|^import " scripts/make_short_auto.py` shows argparse/json/subprocess/sys/pathlib and no `boydclips` import at all, while src/boydclips/render.py already contains `build_ass` (render.py:917), `group_words` (render.py:849), `_watermark_chain` (render.py:1220), `render_short` (render.py:1394) and `detect_tile_crops` (render.py:435). `grep -c "watermark\|manifest\|Store\|sting" scripts/make_short_auto.py` = 1, and that hit is a word in the docstring.
WHY-IT-MATTERS: Everything the package gives for free — the branded sting, the watermark, the manifest with source timestamps and prompt versions that README.md:145-148 promises for every clip, the ledger `boyd stats` reads to decide autonomy promotion — is silently absent from every video made since 2026-08-28, because the code that makes them never opens the package. An unattended system cannot be promoted to `auto` on a ledger its own renderer does not write to.
PROPOSAL: Invert the dependency deliberately rather than by drift. Promote the four measured winners into the package — `gaps.py` (word-gap cutting), `speaker.py` (the A/V correlation from who_speaks.py, measured 9/9), `captions.py` (speaker-side placement), `thumbs/q3.py` — and reduce scripts/make_short_auto.py, scripts/run_case.py and scripts/make_thumbnail_auto.py to argv parsers over them. Rule to hold the line: a script may parse arguments, read config and print; anything touching ffmpeg, a transcript or the store lives in the package. Move every script no live driver calls to `scripts/attic/`.
COST: Three to five days, most of it re-testing. Risk: render.py is 1,600 lines carrying the letterbox/tile logic README.md:152-165 describes, and several scripts import it directly (scripts/make_short.py:41, scripts/rebuild_longform.py, scripts/build_case_longform.py:35-37); moving silence handling out from under them breaks those until updated.

## F3: The hearing-boundary segmenter is phrase-matching used as a proxy for "a new case started", and the repo's own fix for its failure was to have a human type the timecodes in
SEVERITY: blocker
EVIDENCE: Intent, verbatim, at scripts/find_called_hearings.py:1-8 quoting Nathan 2026-08-21 — "the video of that defendant should always start with 'the court is calling'" — and commit fef1220 justifying it: "This phrase appears 3.1 to 5.5 times per docket in EVERY year from 2021 to 2026". The mechanism is one regex, find_called_hearings.py:33 `CALL = re.compile(r"court is calling|the court calls|calling the case")`, and boundaries are consecutive matches, find_called_hearings.py:85 `for a, b in zip(marks, marks[1:] + [len(words)])`. The failure is documented twice: STATE.md:216-220 — "the court never says 'the court is calling' there, which is why `find_called_hearings.py` merged them" — and scripts/build_case_longform.py:1-9, whose docstring says the miss "breaks the one-defendant-per-video rule silently, because the render still succeeds". The repair, build_case_longform.py:16-19, is a command line taking `--in 5915.92 --out-s 6739.30` by hand. Note that 3.1-5.5 matches per docket is far below the number of hearings in a three-hour docket, so silent merging is the normal case, not the edge case.
WHY-IT-MATTERS: This stage decides what a video *is*. A boundary detector that fails silently and whose documented remedy is human-supplied timecodes converts "runs without me putting in much of any input" into "Nathan finds the boundaries". Worse, the failure mode ships a video containing a second, unrelated defendant, which is a publication risk, not merely a quality one.
PROPOSAL: Stop treating the boundary as a lexical event and treat it as a change of party, which is what it is. Build `boydclips/segment.py` emitting a candidate boundary from three independent signals and fusing them: (a) the court's burned-in tile caption changing — OCR already implemented for role assignment at scripts/layout_L1_system.py STAGE B; (b) a speaker-identity change on the non-Boyd tile using the ECAPA embeddings already in src/boydclips/diarize.py; (c) the existing CALL phrase. Then add a hard refusal: if the span's non-Boyd embedding cluster count exceeds one, refuse to render and name the timestamp that splits it. A refusal is recoverable; a silent merge is not.
COST: Four to six days; the OCR and embedding code exist, the fusion and refusal gate are new. Risk: diarize.py needs CPU torch and SpeechBrain (src/boydclips/diarize.py:29-37) so it is slower than a regex, and the pre-July-2025 archive has no speaker markers at all (0e88152: 589 transcripts without against 291 with), so (a) and (b) must carry those years alone.

## F4: Nine selection mechanisms were built, each superseding the last in its commit message and none retired in code, and the three cases actually in production have no recorded selector at all
SEVERITY: high
EVIDENCE: Live and mutually independent on disk, each sourced to its own docstring or creating commit: the Claude rubric in src/boydclips/analyze.py (rewritten by d6bff6d, 757 rows in `cases`); the vocabulary-novelty moment scorer src/boydclips/moments.py + momentrun.py (32d39b2); scripts/find_wentthere.py:1-9 (155ab9c, refit 7de4742, extended 28de204); scripts/find_funny.py:1-9 ([laughter] markers as the label); scripts/find_questions.py:1-9 (punctuation-keyed challenge questions); scripts/find_hearings.py:1-9 and scripts/find_called_hearings.py:1-17 (fef1220); scripts/rank_hearings.py:1-8 (specificity); the three model judges scripts/judge_moments.py:1-9, judge_hearings.py:1-8 and judge_nathan.py:1-9; scripts/top_picks.py:1-11 (predicted performance); plus the exclusion filter src/boydclips/hearingtype.py:1-3 ("Is this a contested evidentiary hearing? If so it is unusable, whatever it scores"). The supersession claims are in the commit bodies — 32d39b2 "The unit was wrong"; 7de4742 "The old scorer scored 61.6 on his posts and 62.4 on his skips — it did not rank at all"; 28de204 "Every vocabulary feature tried today … reversed sign on held-out data". They contradict each other on live numbers: scripts/top_picks.py:1-11 ranks by length using Court Trials TV Network deciles "30-40m 2.53x", while commit 1d83d26 cites the same channel's 970s median as the evidence for the 8-20 minute target now written into spec/SPEC.md. Provenance of the production set: `grep -rn "CARTHIEF\|OFFERUP" --include=*.md .` returns hits only in STATE.md measurement tables and .unlazy/boyd-audit/GATES.md; no commit, docstring or STATE.md paragraph records which of the nine selectors produced CARTHIEF, SANCHEZ or OFFERUP. Their in/out points arrive as literals in config/cases.json (`"case_from": 3574, "case_to": 4628`).
WHY-IT-MATTERS: Selection is the stage that must run unattended if anything does — it is the only one that decides what to make today. Nine candidates and no ranked winner means the answer in practice is "Nathan picked three by hand", and the honest reading of the last three weeks is that the selection stage has never once chosen a published video.
PROPOSAL: Hold one bake-off and then delete. Freeze the 28 labels in state/labels.json plus a fresh unseen batch as a held-out set, run all nine selectors over the same candidate pool, and report precision@10 against Nathan's labels in one table. Keep exactly one selector plus at most one model judge as a re-rank; move the rest to `scripts/attic/` with a one-line note on what each measured. Then write the winner's output into a `selection` table in state/pipeline.db with selector name and version stamped on every row, so a case can never reach cases.json without a recorded reason.
COST: Two to three days to run and score, plus a labelling session with Nathan (his time, unavoidable — this is his taste and cannot be measured without him). Risk: several selectors only cover post-July-2025 dockets, so the comparison must run on the overlapping subset or it measures coverage, not quality.

## F7: `publish.py` was built as stage 4 of an unattended funnel and has never published anything; the blocker is an external fact recorded only in a document marked superseded
SEVERITY: high
EVIDENCE: Intent at src/boydclips/publish.py:1-6: "Stage 4 — publication. The funnel constrains the order: the long-form must publish first so its URL exists before the short's description is written. `publish_pair` enforces that." 331 lines, a `Publisher` Protocol, a YouTube OAuth flow, and README.md:105-126 builds an entire autonomy-promotion ladder on it (`min_consecutive_approvals: 30`, `max_safety_rejects: 0`). The real blocker is stated only in docs/archive/POST-IT-YOURSELF.md:13-15, a file whose own header says "SUPERSEDED — read STATE.md instead": "configuring the Google OAuth client would still not have produced a public video, because Google restricts `videos.insert` from unaudited projects to private." (2) Outcome tracking — this needs no upload permission at all; YouTube Data API videos.list on the channel's own uploads is a read scope. Write views, retention and publish time into a `publications` table keyed to the case. Do that first; it is smaller and it is the one that unblocks selection. Then move the OAuth-audit fact out of docs/archive/ into STATE.md, because a live blocker must not live in a file the README tells people not to plan from.
COST: Outcome tracking, one to two days. The audit path is days of calendar time and out of our hands. Risk: none to existing output; the packaging command overlaps `Pipeline._write_manifest` (src/boydclips/pipeline.py:832) and should reuse it rather than re-derive the metadata.

## F8: `run_case.py` is the current "handle everything from a routine" driver, but its input contract is twelve hand-measured fields per case and neither the driver nor the contract is in git
SEVERITY: high
EVIDENCE: Intent, verbatim, at scripts/run_case.py:1-8: "The routine: one case in, thumbnail and short out. Nathan, 2026-08-29: 'from start to finish can handle everything from a routine' … adding a fourth hearing is a JSON entry, not a code change. That is the whole test of whether this generalises." The JSON entry is thirteen fields (config/cases.json), twelve of them human measurements: offset, case_from, case_to, judge_t, judge_crop ("612:338:18:190"), plate_t, plate_crop, white, yellow, short, short_src_start, and the pre-cut `short` file itself. make_thumbnail_auto.py derives exactly one at run time — plate_t via `pick_plate_time` (scripts/make_thumbnail_auto.py:78-86) — and passes the rest straight through to a subprocess (make_thumbnail_auto.py:91-97). The short stage is a post-processor, not a maker: scripts/make_short_auto.py:4 says "this takes an existing 2-up short". The driver produces no long-form at all — run_case.py:95-119 runs only make_thumbnail_auto.py and make_short_auto.py, while README.md:6-8 and spec/SPEC.md §4 make the long-form the product and the short its advert. And `git status --porcelain -uall` lists config/cases.json, scripts/run_case.py, scripts/make_thumbnail_auto.py, scripts/pick_plate.py and scripts/verify_set.py as `??`; `git check-ignore -v` returns nothing for them, so they are simply uncommitted rather than deliberately ignored.
WHY-IT-MATTERS: The routine automates the last stretch of the job. Everything upstream — find the docket, find the hearing, find its boundaries, cut the 2-up short, measure two Zoom tile rectangles, write the headline — is still Nathan or an operator, which is the opposite of the stated goal. And because the driver and its contract have no git history, there is no record of how the three production cases were configured, and one bad edit loses the only working configuration in the project.
PROPOSAL: Commit these five files today, before anything else in this audit is acted on. Then close the contract from the top: cases.json should be generated, not written — case_from/case_to from the segmenter of F3, judge_crop/plate_crop from `render.detect_tile_crops` (src/boydclips/render.py:435) plus the OCR role assignment in layout_L1 STAGE B, short_src_start from the selected moment, white/yellow from the packaging prompt. ## F10: Two wrappers reason about the world from config strings and comments instead of looking, and both shipped a batch of unbranded video on a false premise
